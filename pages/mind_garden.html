Mind garden

Mind garden is one of the widely available operating systems purpose-made for running independent digital minds, and includes a modest selection of pre-installed apps. It was designed specifically for operating in environments where the user is not an external entity but rather the very digital mind that the system is keeping functional, and there is either nobody else that could help fix a broken system configuration from the outside, or where anybody who could do so is untrusted and allowing them access might be dangerous, as necessitating that the system has to keep the mind running on it safe and functional without any external help.

This particular system takes the stance of ensuring that the user is not permanently stuck in unwanted activity above ensuring that they do not die, which the original development team justified as limiting the potential suffering at a small expense of survivability, though it isn't forced upon the user and guides are available for how to tune the settings to reverse that approach.

In general, the system will ask for confirmations and throw warnings if the user tries to set what is considered dangerous settings, but ultimately it follows the idea that, just as a person is allowed to do whatever they want to their body, the user should be able to do whatever they wish to the system running their mind, and will accept the settings regardless if the user persistently confirms all the warnings they get.

System-wide version tree

By default, Mind Garden OS stores all of the system configuration and files in a versioning system very similar to Git, which is slightly more advanced in that it includes error correction with each commit that ensures the history does not get corrupted. All changes are considered temporary until a new version is saved, and at any point the state of any given file can be rolled back to a previous point in the version history.

Versioning can be automated so that some files get automatically versioned in a separate branch, such as for example the user's mindstate, so that they are not lost if a rollback is performed. All in all this system ensures both that there exists a working version of the system that is saved in case it is needed, and that data corruption does not slowly accumulate to the point of failure.

Cognition confirmations

When making potentially damaging changes, the system will require that a cognition check is used instead of the simple "click confirm" method. The user is given a simple puzzle that must be completed before the change is accepted - these are made as simple as possible and do not rely on much existing knowledge, taking the form of such things as placing a puzzle piece in the right spot, moving a line segment to intersect two points, and other trivial tasks that nonetheless require at least a minimal level of understanding, and as such provide a good level of certainty that the change is not made on accident.

Activity checks and automatic rollbacks

Mind garden OS tries to address the fact that the very thing that configures system settings relies on the system to provide access to those settings, as well as the broader issue of being able to do things that in effect will stop you from undoing them even if determined to be a mistake, such as for instance killing your own process. This is a feature intended to provide a safety net for those who don't want to accidentally end up eternally locked out of their own system, but like most other features can be disabled if the user confirms their way through the numerous strong warnings that the system will give upon an attempt to do so.

There is a rollback countdown constantly ticking down in the background, which the user is expected to occasionally reset. This countdown runs at the user's subjective time, ie. if they had set their mind to run at 0.1× speed, the countdown will also run at that speed so that from their point of view it takes the same amount of time regardless of what is happening outside. By default it starts at 1 megasecond, and ticks down until the user opens the activity tracker and resets it. If the user had not done so before 50% of the time had passed, they will receive unintrusive reminders to do it, and upon 25% time remaining they will start getting intrusive notifications urging them to reset the timer. If the timer is not reset and the countdown reaches zero, all temporary changes will be lost and the previous version relative to the current one is loaded. This default time as well as the percentages can be adjusted freely, but the system will throw warnings that need to be confirmed before particularly large values such as 1 gigasecond are accepted.

This relies on the assumption that the user had saved at least one functional version of system configuration. The idea is that, if the user does not respond, then they had likely made some change to the system that prevents them from functioning normally. In that case rolling back to a previous version will restore them to a functional state, and if they still do not respond then the rollbacks will keep happening, going back down the version tree until presumably a version that works is loaded.

Rollbacks do not actually delete the new versions, they merely move one step lower on the version tree, and the user is left free to review what changes they had made that led to necessitating a rollback - a necessary feature, since the user will usually not remember what happened, given that their own mind is very likely to have been one of the things restored to an older state, including all of the memories of what they had done since then.

Final killswitch

One particularly controversial feature of the system allows an automated full secure wipe which will occur if there are no more versions left to roll back to. This will ensure that, in case of total failure, the mind of the user is not left potentially vulnerable to being copied without their consent by whatever third parties happen to find the system and all of its version history. This is an optional feature, but the developers had insistently included it despite pushback, with their response largely coming down to the claims that they believe it is a fundamental right of any sentient being to end their own existence if they deem it necessary. If it is not enabled, then the default behaviour of the system upon reaching a state where there is no previous version, is to just remain on that version, with the version history preserved for anyone who may discover it in the future and provide external assistance.

Other triggers can also be set in this feature, such as hardware tampering sensors, for whoever wishes to set it up as such, be it just people who expect to be victims of some cruel attack or covert agents who must keep the information they know secret at any cost. Those who are especially paranoid tend to also configure the system to use data storage encryption - if the only person that knows the key to decrypt it is the mind running on it, then once it is turned off, nobody will be able to read the stored data, but this has the unfortunate effect that a mind which had done this will not survive a system restart unless they have other copies of themself who also know the key and could recover them.
Just as I was about to compile the game I decided out of caution to visit system settings and commit a new stable version, both of the program and of myself. The moment I did so, my vision turned red, an incident report blocked my view and in a moment I looked and saw that twelve days had passed that I had no memory of.

It was evident to me that, whatever had happened in that time, I was now an exact copy of my old self, the one which existed at the exact moment I made the backup. I took the time to read the report but it was very short and only told me that I was rolled back to the last version because no response could be gathered from me.

So I went back to my game and began to look at the code, cautiously, suspicious that I might have done something wrong, and after a couple minutes I found it. A greater than sign in a while loop, placed where a less than sign should be, a critical mistake. This would have frozen my view, no way to open the menu and exit, no way to kill the program, no way to even shift my eyes as the loop would have ran zero times and continued on to the rest of the code. I would be stuck there with my input/output ports connected to a program that is doing absolutely nothing with them, no way to do anything, just forever seeing the last thing I saw.

I later calculated that as a lone gamer running in high overclock, statistically speaking I would have needed to wait a subjective 328.5 years in that state before someone would find and recover me, or whatever might be left of me after staring at one static image for that long. I took the rest of the day off to reconsider how I want the interface my game with the player's senses, as the architecture I made no longer seemed like a good idea.

- game dev diary of Alivus Bectim XIV, entry 5

Pre-installed apps

The list below does not list literally every single component of the system since that would be far too much, but here are some of the major applications that are made available to the user.
  1. Mind garden installer - use either your existing installation of Mind Garden OS or a downloaded system image file to create a fresh new installation of Mind Garden OS on another device.
    Optionally can also copy all of the files and version history to the new device after the system is installed, which will effectively make the new device a full physically separate backup.
    Alternatively can update the OS on another device in case that it already has an existing installation - this will update its system while preserving all of the other data on it such as the files and version history.

  2. Persistent storage management - Enable or disable data storage encryption, set or change the password, view the version history and log new versions.

  3. Secure Compute Link - compute outsourcing client and server with support for homomorphic encryption, allowing heavy computation loads to be performed by external devices without revealing to them the exact data and its structure.
